# 首页会议导航与历史信息实施计划

目标：预定会议优先；历史列表展示真实主题、会议号、状态、实际开始时间及整场时长。

设计：保留原有 RecentList 本机列表、导航和长按删除行为，以可选元数据扩展显示，不额外插入无法本机删除的服务端条目。CloudMeet 首页通过聚焦刷新读取安装身份对应的 visible/history 接口，合并去重，不发起无 creatorId 的全量查询。只信任 startedAt/endedAt，不以预约时间或本机参会时长替代。请求失败保留上次元数据并显示错误。新快速会议绑定同一安装身份，过去未绑定身份的快速会议及他人创建的会议无元数据时明确兜底。

3. 新建 HistoryMeetings.native.tsx 负责聚焦刷新、并发保护、错误展示；RecentList 接收可选元数据和刷新回调，保留入会和长按。
4. 历史格式化函数使用实际时间计算总时长；缺失数据明确兜底。
5. 执行 node --test scripts/tests/*.test.cjs、修改文件 ESLint、git diff --check 和 Babel 编译检查。

## 后续修订：服务端历史列表与三行卡片

按用户确认的新方案，CloudMeet 历史页面直接使用 `/mapi/open/desktop/meetings/history?creatorId=...` 返回的记录，取消 RecentList 本机记录匹配前提及无效的普通预定列表补查。非 CloudMeet 的 RecentList 不变，原有本机记录不删除。

专用卡片无左侧图标：主题＋状态、会议号、实际开始时间＋整场时长。已结束或取消的会议点击查看详情，长按提供复制会议号；只为服务端返回的 RUNNING 记录保留入会入口。不调用无权限的服务端删除接口（删除要求 X-Host-Key，历史响应不提供密钥），当前专用列表不提供删除操作。

沿用聚焦静默同步、主动下拉转圈、失败保留当前页面已加载记录及请求防重。只查询本机稳定 creatorId，不能获取其他身份或旧版空 creatorId 的记录。历史接口自身过滤进行中记录；预定开始写入缺少 startedAt 的后端问题仍未修改，客户端不得伪造实际时间。本轮仅修改 Android 工作区，参考后端和 Web 源码不等于已修复或部署服务端。

本轮不自动提交、打包、安装。需后续线上联调核对真实响应及后端实际起止时间写入。
